## Global contracts

The main plugin may use only the closed scope instances declared at
`src/BazaarPlusPlus/Infrastructure/Logging/Core/BppLogSchema.cs:13-41`. Field privacy,
correlation, and cardinality values below are the enums at
`src/BazaarPlusPlus/Infrastructure/Logging/Core/BppLogSchema.cs:93-114`. Every event ID has at
least three dotted-snake segments as enforced by
`src/BazaarPlusPlus/Infrastructure/Logging/Core/BppLogEventCatalog.cs:193-202`.

- Error is one authoritative terminal failure of the current operation, or confirmed data/artifact
  integrity loss. A helper must feed the owner result instead of emitting a second Error.
- Warning means the requested or background operation completed through a reduced-capability,
  reduced-quality, higher-latency, or future-integrity fallback. Retriable health failures emit once
  on `healthy -> degraded`; repeated failures are silent; the first subsequent semantic success
  emits one recovery Info.
- Info is limited to low-frequency lifecycle completion, a user-visible result, or recovery. Routine
  setup, probes, retries, cache hits, internal milestones, and no-op paths are Debug or deleted.
- Debug is compile-time excluded from Release by the #50 pipeline. Exceptions are passed through the
  bounded exception projection, never interpolated into a normal field.
- Warning safety keys contain the event ID and only declared low-cardinality state fields. Error
  keys contain the event ID, all declared correlation, and exception fingerprint when present. An
  Error without correlation or exception is not coalesced.
- Dynamic component strings disappear. Shared adapters receive a closed owning event/context;
  BazaarAgent retains its independent `[BazaarAgent]` prefix and `agent.*` vocabulary.

### Notation

Long form is `field:Privacy:Cardinality:Correlation`. Compact tables use `P` = Public, `U` =
UntrustedText, `S` = Sensitive, `LP` = LocalPath, `RU` = RemoteUri; `L/H` = Low/High cardinality;
`N/Sh/Hs/F` = None/Short/Hash/Full correlation. `exception` always means the bounded exception
projection. An em dash means deletion. In compact D/E rows, the event prefix selects the identically
named closed scope (`collection_panel.*` uses `CollectionPanel`, `settings.*` uses `Settings`, and so
on); a caller-owned alternative selects the scope that matches the chosen event prefix.

### Correlation and privacy policy

| Concept | Field | Privacy | Cardinality | Correlation | Rendering and propagation |
|---|---|---|---|---|---|
| Run | `run_id` | Public | High | Short | Generate/retain the stable run ID; render the first eight characters. |
| Battle | `battle_id` | Public | High | Short | Use the stable battle ID; render the first eight characters. |
| Decision | `decision_id` | Public | High | Short | Generate before the decision-log operation; render the first eight characters. |
| Recording | `recording_id` | Public | High | Short | Generate before capability/preflight gates and carry through the one terminal result. |
| Request | `request_id` | Public | High | Short | Generate at each declared async user/HTTP operation entry, carry through its terminal owner/queue/processor, render eight characters. |
| Screenshot | `screenshot_id` | Public | High | Short | Generate before the first capture attempt and retain across retry/metadata persistence. |

The full value remains in the in-memory structured event for storm identity; the renderer shortens
it. Stable card/merchant/trainer template IDs remain full (`Public:High:None`). Account IDs,
user/display/hero names used as identity, link codes, tokens, headers, bodies, query strings, and
free-form server error text are omitted. Local paths use `LocalPath`; remote text uses
`UntrustedText`; logical endpoint/route values replace raw URLs.

### Upload ambiguity resolved

`StartupUploadAttemptRunner` treats any normally completed `Task` as healthy
(`StartupUploadAttemptRunner.cs:142-152`), while `RunBundleUploadService` catches per-run exceptions,
stores failure text, and still completes normally (`RunBundleUploadService.cs:86-111`). Therefore the
runner alone cannot implement truthful recovery. The manifest decision is to return/callback a typed
semantic attempt result from the feed/service; only that result may drive `upload.feed.recovered`.
The existing dynamic `LogScope` and four prose strings in `IUploadFeed.cs:11-19` become a typed feed
identity/log context rather than a renderer input.

### Decisions that bind #57

1. Scope is fixed: every row below uses `BppLogFeatureScope.CombatReplay` (`combat_replay.*`) or `BppLogFeatureScope.Screenshots` (`screenshots.*`). Helper/class names never become scopes.
2. Correlation is fixed and consistent in this domain: `battle_id`, `recording_id`, `screenshot_id`, and `run_id` are `Public/High/Short`. The renderer displays eight characters while the pipeline retains the full value for error-correlation/storm identity. Hero/player/display/account names are omitted, not logged or hashed. In particular, the current hero value at `SS/EndOfRunScreenshotController.cs:213,220` must disappear.
3. A replay playback owns one optional low-frequency `combat_replay.playback.started` Info and exactly one terminal event: `combat_replay.playback.succeeded` Info, `combat_replay.playback.degraded` Warning, or `combat_replay.playback.failed` Error. Helper failures feed a per-playback degradation/result accumulator; helpers do not emit Warning/Error directly.
4. A requested video recording receives a `recording_id` before capability/preflight checks (the current `VideoId` is only created later in `ReplayVideoCaptureRequest`), then emits exactly one terminal event from a one-shot recorder completion gate: `combat_replay.video_recording.succeeded` Info, `combat_replay.video_recording.degraded` Warning when a usable video survives with reduced audio/metadata quality, or `combat_replay.video_recording.failed` Error when no usable requested artifact survives. No separate recording-start Info is retained.
5. An end-of-run screenshot receives a `screenshot_id` before its first attempt and retains it across the single retry. It emits exactly one terminal `screenshots.capture.succeeded` Info, `screenshots.capture.degraded` Warning when a PNG survives but readiness/metadata is degraded, or `screenshots.capture.failed` Error when no PNG survives. First-attempt failure is Debug state only, never terminal.
6. FFmpeg stderr is untrusted input. `FfmpegRawVideoEncoder` must not emit a log per stderr line (`CR/Video/FfmpegRawVideoEncoder.cs:338`). Both raw-encode and mux stderr collectors must be bounded while reading (not merely truncated after `ReadToEnd`; the current unbounded read is at `CR/Video/ReplayVideoAudioMuxer.cs:246-252`). Only a bounded tail reaches the one terminal event as `stderr_tail:Untrusted/High/None`; central rendering then single-line escapes and truncates it. Absolute executable/output/WAV paths use `LocalPath` fields.
7. Terminal severity is result-based. Error means playback/artifact/persistence irrecoverably failed or replay data was lost. Warning means the requested user-visible result exists but a fallback reduced quality/capability (silent video, bounded readiness fallback, artifact without index metadata). Debug holds probes, milestones, frame/audio statistics, cleanup details, and retry-in-progress. No healthy-path Info in this domain remains except replay start and user-result terminal events.
