# 战斗报告状态带：共享 Y 轴的尺度与布局

- 状态：v16 已实现并通过真实报告、极值、窄屏与跨浏览器验收
- 日期：2026-07-23
- 范围：Viewer 顶部状态带的 Y 轴映射、标注和交互；不改报告采集、状态原始值或事件泳道

## 1. 背景与纠正

Viewer v14 把 Health、Rage、Regeneration、Shield、Burn、Poison 画成六条各自缩放的
20px 小轨。这个方案虽然让每条线都有局部起伏，但不符合产品要求：用户要的是六项状态
与敌我双方真正使用同一个 Y 坐标映射，而不是只共享 X 轴。

v14 的问题不是高度不够，而是坐标语义错误：

- 同一个数值在不同指标上落不到同一个 Y；
- 不同轨的垂直位置不能比较；
- 六个窄轨把 120px 高度切碎，曲线变化仍难读；
- “各自缩放”隐藏了状态量级之间的关系。

## 2. 已确认的产品模型

顶部状态区是一张共享时间轴、共享 Y 轴的多序列图：

- 六项指标和敌我双方共用唯一的 X mapper 与唯一的 Y mapper。
- 指标由颜色区分。
- 我方使用实线，对手使用虚线。
- 相同原始值无论属于哪项指标、哪一方，必须得到完全相同的 Y 坐标。
- 左侧当前值和 hover tooltip 显示原始值；数量级压缩只影响像素位置。
- 缺失值不补 0；真实的 0 才参与绘制。

## 3. v15 的唯一 Y 映射

所有存在的状态采样先统一变换：

`signedOrder(value) = sign(value) * log10(1 + abs(value))`

然后用全体指标、全体敌我样本的 mapped min/max 建立唯一的线性像素域：

1. 域包含真实观测值，并包含 0 基线，以保留正负方向和数量级关系。
2. 非常量域上下保留 8% padding。
3. 全部为 0 时，0 画在状态带中线。
4. `NaN`、`Infinity` 与缺失样本不参与 domain，也不生成伪造曲线。
5. 数值即使达到指数级仍必须保持有限坐标并落在状态带内。

这不是“各项归一化”：`10`、`1,000`、`1,000,000` 在所有序列中始终使用同一数量级
尺度，因此可以比较；代价是高基数上的微小波动不会被人为放大，这正是共享 Y 轴的语义。

## 4. v15 的视觉与交互

- 状态 canvas 保持约 120px，不再切成六个水平 band。
- 绘制少量共享水平参考线和 0 基线，不显示六组独立格线。
- 指标颜色保持稳定；敌我只通过实线/虚线编码，不为双方建立不同色轴。
- 左侧六行保留为图例与播放头当前值；v15 假设移除 canvas 分轨线后便不会再暗示
  每行对应一个独立 Y 轨。
- 状态带、时间标尺、事件泳道继续共宽、共滚动、共播放头。
- 点击或拖动状态带仍更新播放头、当前值、事件上下文与录像时间。

## 5. 验收

真实报告和合成 fixture 都必须通过：

- 状态 canvas 与事件 canvas 等宽，同一 `combatMs` 的 X 误差 `<= 1px`。
- 所有 12 个潜在序列调用同一个 domain 和同一个 Y mapper。
- 任意两个序列在原始值相同时，Y 坐标误差 `<= 0.01px`。
- `0 / 10 / 1e3 / 1e6 / ±1e12` 的 Y 顺序正确、坐标有限且位于画布内。
- 我方为实线、对手为虚线；指标颜色在敌我之间一致。
- 缺失方不出现伪造的 0 线。
- playhead/hover 后左侧敌我值与报告原始采样精确一致。
- 时间缩放、横向滚动、播放头、录像 seek 和事件点击行为无回退。
- `1199×857` 与 `480×857` 下无页面级横向溢出，状态带和实体泳道均可达。

## 6. v15 版本边界

v14 保持不可变，继续表达“六项独立 Y 轨”的历史行为；新模型只进入 v15。旧报告继续
固定引用生成时的 Viewer 版本，不覆盖已安装的 v14 文件。

## 7. v15 验收结果

- 真实报告 `473037830df44c62849b5666174988a0` 的 Health、Regeneration 与 Burn 已在
  同一 120px 状态画布内按共同数量级关系绘制；不再出现六个 20px 小轨。
- 合成 fixture 分别在不同指标/敌我序列中写入原始值 `10`，三条水平段的实测 Y 均为
  `56px`，误差 `0px`。
- `+1e12 / 0 / -1e12` 的主水平线分别位于约 `15px / 60px / 105px`，顺序正确且没有
  NaN、Infinity 或越界。
- 我方实线像素占用率为 `1.0`，对手虚线为 `0.667`；指标色在双方之间保持一致。
- 时间缩放 `100% → 150%` 后状态带、刻度、泳道宽度同时由 `957px` 变为 `1436px`，
  三块 backing scale 均保持 `2.0`。
- 点击状态带定位到约 `4.0s` 后，三层播放头逻辑 X 均为 `525.5px`，误差 `0px`；
  左侧六项原始值同步更新。
- `1199×857` 与 `480×857` 均无 console/page error；窄视口
  `body.scrollWidth === innerWidth === 480`，横向溢出只存在于时间轴内部。

这些验收只证明了像素映射和交互正确，没有证明共享轴在产品上可读。用户查看真实报告后
明确反馈“怪怪的”，因此 v15 不能作为视觉验收通过版本。

## 8. v15 视觉失败的根因

真实报告在约 `10.7s` 的代表值为：Health `我 1,333 / 敌 491`、Regeneration
`我 103`、Burn `敌 601`。v15 的 signed-order 映射把它们放在约
`21px / 28px / 40px / 27px`；若使用共享线性原始值轴，则约为
`65px / 93px / 106px / 89px`。

当前画面“怪”来自三项相互叠加的问题：

1. 左侧仍是六个等高行，视觉上继续表达“每项对应一条水平轨”；右侧曲线却可以跨越任意
   行，标签和曲线的空间关系互相矛盾。
2. signed-order 是隐藏变换，画面没有 Y 刻度或尺度名称；用户无法从垂直距离还原
   `103 / 601 / 1,333` 的数量关系。
3. 左侧承担了图例、当前值和伪 Y 轴三种职责；真正的共享 Y 轴反而没有任何可见刻度。

这次失败说明“同值同 Y”的像素断言是必要条件，不是完整的 UI 验收。

## 9. 修订候选

### A. 保持隐藏的数量级轴，仅补刻度

- 优点：改动小，指数级数据始终可见。
- 缺点：普通战斗中的数值比例仍被压缩；即使补刻度，也会让基础状态图默认呈现一种较
  专业但不直观的变换。

### B. 默认共享线性轴，显式提供“线性 / 数量级”切换（推荐）

- 默认线性轴直接表达原始值比例；`601` 与 `1,333` 的高度关系可直读。
- 数量级模式仍使用统一 signed-order mapper，专门处理指数级战斗。
- Viewer 不自动偷偷换轴；当前模式必须在 UI 中可见。
- 两种模式都共享敌我和六项指标的同一个 Y mapper，不退回独立轨。

### C. 自动根据跨度切换线性/数量级

- 优点：无需用户操作。
- 缺点：同一套 UI 的垂直距离会随战斗数据自动改变，难以建立稳定预期；仍存在隐藏语义，
  不推荐。

## 10. 推荐布局

- 左侧状态单元明确分成两块：
  - “当前值”表：六项颜色、名称、我方值、对手值；使用卡片/表格语义，不再假装与曲线
    Y 位置对齐。
  - 真正的 Y 轴 gutter：根据当前模式显示 3–6 个刻度。
- 状态画布显示当前轴模式和共享参考线；颜色区分指标、实线/虚线区分敌我。
- hover/playhead 更新“当前值 · 10.7s”时间标题，明确这些数值属于哪一帧。
- “线性 / 数量级”切换放在状态区而不是全局事件工具栏，并保留时间缩放、播放头和录像
  联动。

## 11. 修订方案验收

- 默认打开真实报告时必须明确显示“线性”，且 Y 刻度与原始值一致。
- 切换“数量级”后，刻度与曲线同步变化；再次切回线性，像素与初始状态完全一致。
- 左侧当前值表和 Y 刻度具有清晰的视觉分区；不得再形成六个标签行对应六条轨的暗示。
- 在线性模式中，相同原始值跨指标/敌我仍同 Y；`601` 与 `1,333` 的高度比例可由刻度
  解释。
- 在数量级模式中，`±1e12` 有限且可见；模式标签不能被隐藏。
- 两种模式下状态带、标尺、泳道的 X 对齐误差仍 `<= 1px`。

## 12. v16 实现与验收结果

- 默认模式为共享原始值线性轴；真实报告显示 `0 / 1,000 / 2,000 / 3,000`
  刻度，Health、Regeneration 与 Burn 的垂直关系可由原始值直接解释。
- 左侧 120px 状态单元拆成“当前值表 + Y 轴 gutter”；播放头或 hover 后标题更新为
  `当前值 · <combat time>`，不再把六行标签伪装成六条独立轨。
- “线性 / 数量级”是状态区内的显式双态按钮，使用 `aria-pressed` 暴露状态。真实报告
  完整切换为 `linear → magnitude → linear` 后，刻度恢复为初始集合。
- 数量级模式继续使用统一 signed-order mapper；合成 fixture 的 `±1e12` 得到有限域
  `[-13.92, 13.92]`，Canvas backing scale 保持 `2.0`。
- 时间缩放 `100% → 150%` 后状态 canvas 由 `941px` 扩为 `1,412px`，轴模式保持
  `magnitude`、刻度不漂移；hover 同步更新当前值时间到 `3.90s`。
- Chromium 在 `1199×857`、`480×857` 下均满足
  `documentElement.scrollWidth === innerWidth`，状态单元无内部溢出、两个轴模式按钮均
  可见，时间轴可视高度为 `783px`。
- WebKit 在 `1199×857` 下得到相同的线性/数量级刻度、DPR 与布局。隔离运行时记录到
  一条既有 CSP 内联样式警告，但页面样式、状态轴与交互均正常；该警告不由 v16 状态轴
  代码引入。
- 全零 fixture 使用 `[-1, 1]` 有限域；完全缺失状态采样时不生成伪造刻度或曲线，两者
  均无 page error。

v15 已冻结到版本化资源目录；新报告引用 v16，旧报告继续使用生成时的 Viewer 版本。
