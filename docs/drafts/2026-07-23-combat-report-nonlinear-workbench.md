# 战斗报告 Viewer：非线性浏览工作台改版

- 状态：用户已确认，v6 实施验证中
- 日期：2026-07-23
- 范围：共享静态 Viewer 的录像/时间轴布局与交互；不改录像编码、码率、裁切、报告发布或 Asset Cache

## 1. 已验证事实

真实 v5 报告在 Chromium、`838×857` 视口下：

- 录像展开：录像 section 高 `559px`，视频画面高 `459px`；时间轴从 `y=609` 才开始，无法同时浏览录像和泳道。
- 录像折叠：时间轴滚动区高 `323px`，54px 泳道约可见 `5.98` 条；但录像完全不可见。
- `480×857` 同样二选一：折叠时约可见 `5.11` 条泳道；展开后录像 section 高 `417px`，时间轴从 `y=467` 才开始。
- 当前交互只在“悬停到事件 marker 且视频暂停”时通过 `currentTime` 跳转；点击 marker 固定事件并把 inspector 放到时间轴底部。
- 当前没有持续可见的播放头、任意时刻 scrub、播放跟随、上一/下一事件 transport，也没有区分“临时预览时间”和“已固定时间”。

## 2. 本轮纠正与根因

错在把“录像可完整观看”直接实现成全宽 16:9 展开块。它单独看录像没问题，但破坏了战斗报告最重要的并行关系：**画面、时间位置、事件上下文必须同时可见**。

为什么之前没发现：验收只量了“录像能否播放”和“折叠后可见泳道数”，没有把“录像可见时仍可操作几条泳道”作为联合断言。

防复发：本轮以后同时验收监视器、时间轴和 inspector 的组合布局；不能分别截图后判定通过。

## 3. 候选布局

### A. 继续上下展开/折叠

- 优点：改动小。
- 缺点：录像与时间轴仍然互斥；不是非线性浏览体验。
- 结论：淘汰。

### B. 浮动/PiP 录像

- 优点：不压缩时间轴。
- 缺点：遮挡事件；需要拖拽、停靠、记忆位置，移动端和无障碍成本高。
- 结论：只保留为未来可选模式，不作为默认。

### C. 紧凑上层工作台 + 全宽时间轴（推荐）

```text
┌──────────────────────────────────────────────────────────┐
│ Match summary                                            │
├──────────────────┬───────────────────────────────────────┤
│ 录像监视器 16:9   │ 当前帧 / 选中事件摘要                 │
│ 约 240×135       │ 同帧事件、来源、目标；可展开完整列表   │
│ ⏮  ▶  ⏭  03.15  │                                       │
├──────────────────┴───────────────────────────────────────┤
│ Timeline ruler / playhead / zoom / follow                │
├──────────────────────────────────────────────────────────┤
│ Metrics                                                  │
├───────────────┬──────────────────────────────────────────┤
│ Entity lanes  │ Event canvas                             │
└───────────────┴──────────────────────────────────────────┘
```

- 录像是“参考监视器”，不是独立大章节；默认始终可见但高度受限。
- 当前帧 inspector 使用监视器右侧的剩余空间，不再占用时间轴底部。
- 时间轴保持全宽，避免右侧常驻 rail 把 838px 视口中的事件画布压得过窄。
- `<= 700px` 时仍保持“紧凑监视器 + inspector”并排，但监视器固定为 `168px`，隐藏非关键 transport；不再切成会额外占用纵向空间的第二套布局。
- 提供全屏录像按钮，但全屏是显式动作，不改变主工作区布局。

## 4. 交互状态模型

Viewer 只维护一个 authoritative `playheadMs`，另有两个短暂状态：

- `previewMs`：鼠标悬停或拖动时的临时预览，不改变 inspector 的固定选择。
- `committedMs`：点击、键盘跳转或播放暂停后固定的时刻。
- `selectedFrame`：固定时刻对应的完整同帧事件组；marker 聚合必须可逆。

### 4.1 时间轴

- 悬停任意空白位置：显示 ghost playhead，并预览对应视频帧；悬停 marker 时额外高亮来源、触发方和目标。
- 单击空白：固定任意时刻，并显示该帧/邻近窗口的所有事件。
- 单击 marker：固定到该 frame，打开完整同帧事件组。
- 拖动：连续 scrub；`pointerup` 后才提交 inspector 选择。
- 播放中：实线 playhead 按视频实际呈现帧前进；必要时自动横向跟随。
- 用户手动横向滚动后暂停跟随，点击“跟随播放头”恢复。

### 4.2 Transport

- `Space`：播放/暂停。
- `←` / `→`：上一/下一报告事件；`Shift+←/→`：小步时间移动。
- 监视器提供上一事件、播放/暂停、下一事件、当前战斗时间、全屏。
- 不再显示第二条独立视频进度条；时间轴本身就是主 scrub surface。

### 4.3 Seek 性能

- pointermove 只更新内存中的目标时间；最多每个 animation frame 合并一次 UI 更新。
- 媒体仍在 `seeking` 时只保留最新目标，`seeked` 后再执行；避免排队解码几十次过期 seek。
- hover preview 可用 `fastSeek` 时优先快速预览；点击/拖动结束使用精确 `currentTime`。
- 播放头由 `requestAnimationFrame` 驱动并读取 `video.currentTime`；不依赖低频 `timeupdate`，也不让视频源帧率限制 UI 刷新率。真实录像验证中，`requestVideoFrameCallback` 的 145 帧窗口 p95 为 21.5ms，因此不适合作为 60fps UI playhead 的唯一时钟。
- 不通过调整录像 GOP、编码或分辨率解决本轮问题。

## 5. 保持不变的三项不变量

- 全部事件可达。
- 时间位置可还原。
- 聚合可逆；同帧事件永远能进入完整列表。

## 7. 本轮明确不做

- 不改视频录制参数、压缩、裁切或录屏区域。
- 不引入 HTTP/Tauri Viewer。
- 不重做 report JSON、Asset Cache 或发布路径。
- 不把事件从时间轴移走来换空间。

## 8. 当前验证证据

- 真实 metrics 报告：`838×857` 下 workbench `148px`、metrics `130px`、timeline `312px`、可见泳道 `5.78`；横向溢出 `0px`。
- 同一报告：`1280×900` 下 timeline `354px`、可见泳道 `6.56`；`480×857` 下 timeline `282px`、可见泳道 `5.22`，横向溢出 `0px`。
- Exact-sync 真实录像：任意时间点击后战斗时间 `3.950s` 映射到视频 `4.233s`；下一事件跳到 `4.000s`，同帧 inspector 展示 `22` 条事件。
- 泳道缩放从 `100%` 到 `125%` 时行高由 `54px` 变为 `68px`；时间缩放从 `100%` 到 `150%` 时画布宽由 `720px` 变为 `976px`，两个轴互不耦合。
- Exact-sync 真实录像连续播放 10 秒：采集窗口 `1200` 帧，p95 `10.3ms`、最大 `21.9ms`、`>25ms` 为 `0`。
- `./run.sh build --fast` 为 `0 warning / 0 error`；四个 Report 定向项目和 `./run.sh test` 全量回归均通过。
- 当前自动化 Browser 的 URL policy 禁止打开 `file://`，因此本轮无法从该工具重复执行 Chrome/Safari 文件协议实测；静态 gate 仍由“无 fetch/module/Worker、相对资源 URL、单一 classic bundle”契约测试覆盖，实际浏览器 gate 保留为待验证项。
- 版本冻结要同时更新主工程和 `CombatReplayReportBundle.Tests` 的显式 EmbeddedResource 清单；仅改主工程不会被 exe-runner 自动继承。本轮已由首次定向测试失败捕获并修正。
