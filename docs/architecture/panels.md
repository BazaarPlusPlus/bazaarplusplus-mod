# Overlay Panels, History, And Live Build

Main-overlay-panel lifecycle, the native HistoryPanel surface, and the board adapters used by HistoryPanel and LiveBuildPanel.

`Game/OverlayPanels/OverlayPanelHost.cs` is the single Unity adapter that owns main-overlay-panel lifecycle: it reads per-frame input (escape, panel toggle hotkeys, combat state, scene changes), runs the pure `OverlayLifecycleCore` rules, and dispatches open/close/tick to registered panels (`src/BazaarPlusPlus/Game/OverlayPanels/OverlayPanelHost.cs`). It mounts before every panel mount, and CollectionPanel, HistoryPanel, and LiveBuildPanel all register through its accessor, enforcing at-most-one-open-panel (`src/BazaarPlusPlus/BppComposition.cs`). Lifecycle tests live in `tests/OverlayPanelLifecycle.Tests/`.

HistoryPanel is mounted through `HistoryPanelMount` with a single-constructor `HistoryPanelDependencies` (run state, data service, replay service, optional probe/link surfaces, and the combat-replay directory path as a plain string); run state is the read-only two-member `IHistoryPanelRunState` (`IsInGameRun`, `CurrentServerRunId`) adapting `IRunContext` (`src/BazaarPlusPlus/Game/HistoryPanel/IHistoryPanelRunState.cs`, `src/BazaarPlusPlus/Game/HistoryPanel/HistoryPanelDependencies.cs`). Its owned uGUI view uses native artwork, portraits and trophies with scrolling run/battle lists (`src/BazaarPlusPlus/Game/HistoryPanel/Ui/HistoryPanelView.cs`). `HistoryPanel.NativeBoards.cs` projects a single normalized snapshot set into native cards and skills for `GameInterop/MonsterBoardPreview/OwnedMonsterBoardPreview.cs`. Each adapter owns a `MonsterBoardTooltip` clone, preserves native card pooling, and fits the carpet independently of its scrolling skills. The opponent is above the player; neither native history controllers nor the active monster tooltip are reused.

HistoryPanel keeps replay, recording and deletion beside the archive. Its More dialog contains database status, remote health probing, supporter attribution and the BazaarDB account-link form (`src/BazaarPlusPlus/Game/HistoryPanel/Ui/HistoryPanelView.Actions.cs`). The dialog owns a foreground canvas above the native board canvases. The account-link card POSTs a one-time code to the bazaardb.gg redeem endpoint through `BazaarDbLinkClient`, built at startup on a dedicated 30s-timeout HttpClient independent of the mod-api base URL (`src/BazaarPlusPlus/Plugin.cs`), with link state persisted by `Game/HistoryPanel/AccountLink/BazaarDbAccountLinkStore.cs`. Server health display state is derived from the mod API health probe result without changing storage state (`src/BazaarPlusPlus/Game/HistoryPanel/HistoryPanelServerHealth.cs`).

`HistoryPanelMenuEntry` appends an owned data row after merchandise in the native navigation menu. `HistoryPanelMenuPatches` reaches it through `BppPatchHost`. Accepted replay launches retain the history origin; when the replay session finishes and `SceneLoader.ActiveScene` is `HeroSelectScene`, the panel reopens with its selection and scroll positions preserved.

`GameInterop/ItemBoardPreview` provides board planning shared by HistoryPanel and LiveBuildPanel. `BppItemBoardSlotPlanner` plans cards onto a 10-socket board, with special handling for selectable shop/container boards (`src/BazaarPlusPlus/GameInterop/ItemBoardPreview/BppItemBoardSlotPlanner.cs`). Both panels project planned items through `NativeMonsterBoardItemMapper` and render owned native `MonsterBoardTooltip` instances through `GameInterop/MonsterBoardPreview`; Collection retains the shared measured frame-height proportion for its independent card fitter.

LiveBuildPanel owns an opaque full-screen uGUI view over the native Collection background. A right overview holds the title with a top-right close action, a compact corpus section with its refresh action in the heading and freshness/status underneath, larger recommendation navigation controls below, and a vertical supporter list. Four simultaneous peer sections on the left show recommendation, shop, stash, and current board; fine rules and spacing separate their contents over one consistently dimmed native backdrop, with a stronger rule for the recommendation. The overview uses a vertical rule rather than an opaque slab. Navigation chevrons use one closed mesh with shared vertices through the elbow. `LiveBuildPanelLayout` divides the height-scaled canvas between equal item-only carpet regions after reserving headers, metrics, and candidate tags. Native sockets and size spans determine placement. Titles, empty/loading status, and metrics align with the loaded carpet's horizontal bounds; those bounds position the overview and section decoration without resizing the preview region itself. Candidate state remains feature-owned and keyed by template id across selectable sources; the native adapter reports loaded frame geometry and template identity, and the view positions non-interactive native-art tags beneath those frames. Native hover stays on the prefab. Replacement and close synchronously end the tracked hover; close hides and detaches each owned root before waiting for native acquisition to finish and returning registered cards to the native pool. No card setup is cancelled mid-acquisition. A weak identity gate rejects late native tooltip shows after the owning board retires, without hiding another owner’s tooltip.
