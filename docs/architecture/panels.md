# Overlay Panels, History, And Live Build

Main-overlay-panel lifecycle, the HistoryPanel surface and its right rail, and the shared item-board preview adapter that HistoryPanel and LiveBuildPanel both consume.

`Game/OverlayPanels/OverlayPanelHost.cs` is the single Unity adapter that owns main-overlay-panel lifecycle: it reads per-frame input (escape, panel toggle hotkeys, combat state, scene changes), runs the pure `OverlayLifecycleCore` rules, and dispatches open/close/tick to registered panels (`src/BazaarPlusPlus/Game/OverlayPanels/OverlayPanelHost.cs`). It mounts before every panel mount, and CollectionPanel, HistoryPanel, and LiveBuildPanel all register through its accessor, enforcing at-most-one-open-panel (`src/BazaarPlusPlus/BppComposition.cs`). Lifecycle tests live in `tests/OverlayPanelLifecycle.Tests/`.

HistoryPanel is mounted through `HistoryPanelMount` with a single-constructor `HistoryPanelDependencies` (run state, data service, replay service, optional probe/link surfaces, and the combat-replay directory path as a plain string); run state is the read-only two-member `IHistoryPanelRunState` (`IsInGameRun`, `CurrentServerRunId`) adapting `IRunContext` (`src/BazaarPlusPlus/Game/HistoryPanel/IHistoryPanelRunState.cs`, `src/BazaarPlusPlus/Game/HistoryPanel/HistoryPanelDependencies.cs`). It renders battle previews by asking the shared item-board preview renderer to render a projected board and handling preview phases (`src/BazaarPlusPlus/Game/HistoryPanel/HistoryPanel.cs`).

HistoryPanel's right rail contains local database status, remote server health probing, runs/ghost tabs, ghost filters, delete/replay controls, status text, and a collapsible BazaarDB account-link card (`src/BazaarPlusPlus/Game/HistoryPanel/Ui/HistoryPanelUiToolkitView.Tree.cs`). The account-link card POSTs a one-time code to the bazaardb.gg redeem endpoint through `BazaarDbLinkClient`, built at startup on a dedicated 30s-timeout HttpClient independent of the mod-api base URL (`src/BazaarPlusPlus/Plugin.cs`), with link state persisted by `Game/HistoryPanel/AccountLink/BazaarDbAccountLinkStore.cs`. Server health display state is derived from the mod API health probe result without changing storage state (`src/BazaarPlusPlus/Game/HistoryPanel/HistoryPanelServerHealth.cs`).

`GameInterop/ItemBoardPreview` is the shared board-rendering adapter for HistoryPanel and LiveBuildPanel. `BppItemBoardSlotPlanner` plans cards onto a 10-socket board, with special handling for selectable shop/container boards (`src/BazaarPlusPlus/GameInterop/ItemBoardPreview/BppItemBoardSlotPlanner.cs`). Its surface owns only an injected native-preview host, a per-surface scope, and opaque sessions; its canvas remains `ScreenSpaceOverlay` (`src/BazaarPlusPlus/GameInterop/ItemBoardPreview/ItemBoardPreviewSurface.cs`), so the overlay keeps native rendering while UI Toolkit owns layout; the RT path is closed (`docs/MEMORY.md`, Gotchas).
